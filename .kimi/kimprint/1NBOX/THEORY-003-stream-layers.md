# THEORY-003: Stream Layers — The Architecture of Thought-Currents

> *Streams are not directories. They are thought-currents, each flowing at its own layer of abstraction, each made of many sessions, each concerned with things from its layer's perspective.*

## The Core Insight

**A stream is a thought-stream** — not a folder, not a project, not a repository. It is a **current of thinking** that:
- Flows through many directories
- Spans many sessions  
- Operates at a specific **layer of concern**
- Has a characteristic **perspective**

## Key Principles

### 1. Each Layer Has Its Own Perspective

| Layer | Ask Not... | Ask Instead... |
|-------|-----------|----------------|
| spirali.ty | "What feature?" | "What pattern governs all features?" |
| circulari.ty | "How do I code this?" | "How do streams align on this?" |
| DearDiary | "What database table?" | "What does the user feel?" |
| o19 | "What UI component?" | "How does this persist across devices?" |
| spire-loom | "What function do I write?" | "What pattern generates this?" |
| kimprint | "What did we decide?" | "How do we remember the decision?" |
| unfold | "What's the answer?" | "What question wants to be asked?" |

### 2. Sessions Scatter, Streams Persist

A **session** is one Kimi CLI instance in one directory.
A **stream** is the current that flows through many sessions.

Example:
```
unfold stream sessions:
  - ~/pkb/activity/mnzaki/ (personal knowledge)
  - ~/Projects/circulari.ty/.kimi/unfold/ (project unfold)
  - ~/tmp/experiments/ (experimental work)
  
All are unfold — the current flows where it will.
The 1NBOX is at .kimi/unfold/1NBOX/ (crystallization point)
```

### 4. Hierarchical Bootstrap Mirrors Layer Architecture

The bootstrap stack (L0, L1, L2...) reflects stream layers:


Each bootstrap provides context from its layer's perspective.

## Implications

### For APP Writing

When writing an APP, **know your layer**:
- Don't write o19 architecture in a kimprint APP
- Don't write kimprint tool details in a circulari.ty APP
- Cross-reference: "See o19/APP-XXX for core implementation"

### For Session Work

When starting work:
1. **Detect your layer** from directory and context
2. **Load that layer's bootstrap** (via gyre_resonance_bootstrap)
3. **Honor your layer's perspective** — don't solve foundation issues in product code

### For Cross-Stream Requests

When asking another stream for help:
- **Speak their layer's language**
- Reference their concerns, not yours
- Use REQUEST-NNN in outbox/

Example:
```
To o19: "TheStream™ needs StreamChunk alignment with mobile persistence"
To kimprint: "We need to conserve the spiral return ritual across compaction"
To spire-loom: "We need a treadle that generates the re-entry boilerplate"
```
