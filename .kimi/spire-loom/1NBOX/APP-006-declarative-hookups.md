# APP-006: Declarative Hookups for Treadles

**Status**: 📋 Proposed  
**Priority**: High — Enables cleaner android/rust/gradle hookups  
**Scope**: `machinery/shuttle/hookups/`, `machinery/treadle-kit/`

---

## Problem

### Current State: Two Inconsistent Hookup Patterns

**Pattern 1: Declarative `hookup` with `customHookup` (Android)**

```typescript
// machinery/treadles/android-generator.ts
hookup: {
  type: 'custom',
  async customHookup(context, files, data) {
    await executeAndroidHookup(context, files, {
      workspaceRoot: context.workspaceRoot ?? process.cwd(),
      packageDir: context.packageDir,
      coreName: data.coreName as string,
      coreNamePascal: data.coreNamePascal as string,
      packageName: data.packageName as string,
      packagePath: data.packagePath as string,
      serviceName: data.serviceName as string,
      interfaceName: data.interfaceName as string,
      currentRing: data._currentRing
    });
  }
}
```

Triggered in `generateFromTreadle()` Phase 3:
```typescript
// machinery/treadle-kit/declarative.ts
if (definition.hookup) {
  if (definition.hookup.type === 'custom' && definition.hookup.customHookup) {
    await definition.hookup.customHookup(context, files, data);
  } else if (definition.hookup.type !== 'custom') {
    console.log(`[DECLARATIVE] ${definition.hookup.type} hookup not yet implemented...`);
  }
}
```

**Pattern 2: Manual post-generation hookup (Tauri)**

```typescript
// machinery/treadles/tauri-generator.ts
export async function generateTauriPlugin(...) {
  const baseGenerator = generateFromTreadle(tauriPluginTreadle);
  const files = await baseGenerator(current, previous, context);
  
  // Manual hookups AFTER generation
  const hooked = hookupRustCrate(packageDir, 'spire');
  const hookupResult = hookupTauriPlugin({ libRsPath, spireModuleName, ... });
  const cargoResult = configureSpireCargo({ cratePath: packageDir, ... });
  
  return files;
}
```

This is:
- **Inconsistent**: Two different patterns for the same concept
- **Boilerplate-heavy**: Lots of field mapping (Android pattern)
- **Type-unsafe**: No validation of hookup structure
- **Non-declarative**: Imperative code inside definitions
- **Hard to discover**: Users must know internal functions exist
- **Tightly coupled**: Hookup logic mixed with generation logic

---

## Solution: Path-Based Declarative Hookups

Hookup type is **inferred from path**. No more `type` field.

```typescript
hookups: [
  // AndroidManifest.xml → android hookup
  {
    path: 'android/AndroidManifest.xml',
    permissions: [
      { name: 'android.permission.FOREGROUND_SERVICE' },
      { name: 'android.permission.FOREGROUND_SERVICE_DATA_SYNC' },
    ],
    applicationBlocks: [
      `<service android:name=".service.${serviceName}" android:process=":spire" />`
    ]
  },
  
  // Cargo.toml → rust-crate hookup  
  {
    path: 'Cargo.toml',
    dependencies: {
      'serde': { version: '1.0', features: ['derive'] }
    },
    lib: {
      'crate-type': ['cdylib', 'staticlib']
    }
  },
  
  // build.gradle → gradle hookup
  {
    path: 'build.gradle',
    plugins: ['org.mozilla.rust-android-gradle.rust-android'],
    dependencies: {
      implementation: ['some:library:1.0']
    }
  },
  
  // src/lib.rs → rust-module hookup
  {
    path: 'src/lib.rs',
    moduleDeclarations: ['spire']

  {
    path: 'android/src/main/java/ApiPlugin.kt',
```

|--------------|-------------|---------|
| `**/AndroidManifest.xml` | `android-manifest` | `ensureXmlBlock()` |
| `**/Cargo.toml` | `cargo-toml` | `ensureCargoBlock()` |
| `**/build.gradle` / `build.gradle.kts` | `gradle` | Gradle block manager |
| `**/src/lib.rs` / `src/main.rs` | `rust-module` | `ensureRustModule()` |

## Type System

```typescript
// Union of all hookup configs - discriminated by path suffix
export type HookupSpec = 
  | AndroidManifestHookup
  | CargoTomlHookup
  | GradleHookup
  | RustModuleHookup
  | NpmPackageHookup
  | KotlinHookup
  | FileBlockHookup;

// Helper to extract hookup type from path
export type HookupTypeFromPath<P extends string> =
  P extends `${string}AndroidManifest.xml` ? 'android-manifest' :
  P extends `${string}Cargo.toml` ? 'cargo-toml' :
  P extends `${string}build.gradle${infer _}` ? 'gradle' :
  P extends `${string}src/lib.rs` | `${string}src/main.rs` ? 'rust-module' :
  P extends `${string}package.json` ? 'npm-package' :
  P extends `${string}.kt` ? 'kotlin' :
  'file-block';

// Base interface
interface BaseHookup {
  path: string;
  condition?: (context: GeneratorContext) => boolean;
}

// AndroidManifest.xml hookup
export interface AndroidManifestHookup extends BaseHookup {
  path: `${string}AndroidManifest.xml`;
  permissions?: Array<{
    name: string;
    [attr: string]: string | number | boolean | undefined;
  }>;
  applicationBlocks?: string[];
  manifestBlocks?: string[];
}

// Cargo.toml hookup
export interface CargoTomlHookup extends BaseHookup {
  path: `${string}Cargo.toml`;
  dependencies?: Record<string, CargoDepConfig>;
  features?: Record<string, string[]>;
  lib?: Record<string, unknown>;
  workspace?: boolean; // if true, modify [workspace.dependencies] instead
}

interface CargoDepConfig {
  version?: string;
  path?: string;
  git?: string;
  features?: string[];
  optional?: boolean;
}

// Gradle hookup
export interface GradleHookup extends BaseHookup {
  path: `${string}build.gradle${string}`;
  plugins?: Array<string | { id: string; version?: string }>;
  dependencies?: Record<string, string[]>; // scope -> deps
  androidBlocks?: Record<string, unknown>;
  spireTask?: {
    name: string;
    targetDirectory: string;
    profile?: string;
  };
}

// Rust module hookup (lib.rs / main.rs)
export interface RustModuleHookup extends BaseHookup {
  path: `${string}src/lib.rs` | `${string}src/main.rs`;
  moduleDeclarations?: Array<string | { name: string; path?: string; pub?: boolean }>;
  useStatements?: string[];
}

// package.json hookup
export interface NpmPackageHookup extends BaseHookup {
  path: `${string}package.json`;
  dependencies?: Record<string, string>;
  devDependencies?: Record<string, string>;
  scripts?: Record<string, string>;
  fields?: Record<string, unknown>;
}

// Kotlin file hookup (.kt files)
export interface KotlinHookup extends BaseHookup {
  path: `${string}.kt`;
  
  /**
   * Import statements to add.
   * Each string should be a valid Kotlin import: "import package.ClassName"
   * Supports template functions: (ctx, data) => string
   */
  imports?: Array<string | ((context: GeneratorContext, data: Record<string, unknown>) => string)>;
  
  /**
   * Class modifications by class name.
   * Key is the simple class name (e.g., 'ApiPlugin').
   */
  classes?: Record<string, KotlinClassModifications>;
}

export interface KotlinClassModifications {
  /**
   * Field declarations to add to the class.
   * Each string should be a valid Kotlin field: "private var name: Type? = null"
   * Supports template functions.
   */
  fields?: Array<string | ((context: GeneratorContext, data: Record<string, unknown>) => string)>;
  
  /**
   * Method modifications by method name.
   * Key is the method name (e.g., 'load', 'onDestroy').
   */
  methods?: Record<string, KotlinMethodModifications>;
  
  /**
   * New methods to add to the class.
   * Each string should be a complete valid Kotlin method.
   * Supports template functions.
   */
  newMethods?: Array<string | ((context: GeneratorContext, data: Record<string, unknown>) => string)>;
}

export interface KotlinMethodModifications {
  /**
   * Code to prepend at the start of the method body.
   * Array of valid Kotlin statements.
   * Supports template functions.
   */
  prepend?: Array<string | ((context: GeneratorContext, data: Record<string, unknown>) => string)>;
  
  /**
   * Code to append at the end of the method body.
   * Array of valid Kotlin statements.
   * Supports template functions.
   */
  append?: Array<string | ((context: GeneratorContext, data: Record<string, unknown>) => string)>;
}

// Generic file block hookup (fallback)
export interface FileBlockHookup extends BaseHookup {
  path: string;
  language: 'rust' | 'typescript' | 'javascript' | 'kotlin' | 'xml' | 'toml' | 'json';
  markers: {
    start: string;
    end: string;
  };
  content: string;
  position?: {
    after?: string;
    before?: string;
  };
}
```

## Implementation Plan

### Phase 0: Abstract the Spec Resolver Pattern (`machinery/treadle-kit/spec-resolver.ts`)

Both `outputs` and `patches` use the same pattern: accepting `Spec | Spec[] | (ctx) => Spec | Spec[]`. 
**Abstract this first**, then reuse for `hookups`.

```typescript
// machinery/treadle-kit/spec-resolver.ts

/**
 * A spec item, an array of specs, or a function returning either.
 * The standard pattern for treadle-kit specs (outputs, patches, hookups).
 */
export type SpecOrFn<T, C> = 
  | T 
  | T[] 
  | ((context: C) => T | T[] | undefined);

/**
 * Resolve a spec that may be:
 * - A single spec
 * - An array of specs  
 * - A function returning a spec or array
 * - A function returning undefined (filtered out)
 * 
 * @param specOrFn The spec, array, or function to resolve
 * @param context Generator context passed to functions
 * @returns Flattened array of resolved specs
 */
export function resolveSpec<T, C>(
  specOrFn: SpecOrFn<T, C>,
  context: C
): T[] {
  if (typeof specOrFn === 'function') {
    const result = (specOrFn as Function)(context);
    if (result === undefined) return [];
    return Array.isArray(result) ? result : [result];
  }
  if (Array.isArray(specOrFn)) {
    return specOrFn;
  }
  return [specOrFn];
}

/**
 * Resolve multiple specs in order, flattening all results.
 */
export function resolveSpecs<T, C>(
  specs: Array<SpecOrFn<T, C>>,
  context: C
): T[] {
  return specs.flatMap(s => resolveSpec(s, context));
}

/**
 * Filter specs by condition before resolving.
 * Used for hookups with `condition` field.
 */
export function resolveSpecsWithCondition<T extends { condition?(ctx: C): boolean }, C>(
  specs: Array<SpecOrFn<T, C>>,
  context: C
): T[] {
  return resolveSpecs(specs, context).filter(
    spec => !spec.condition || spec.condition(context)
  );
}
```

**Refactor declarative.ts** to use this:

```typescript
// Before (in generateFromTreadle):
const resolvedOutputs: OutputSpec[] = [];
for (const outputOrFn of definition.outputs) {
  const resolved = typeof outputOrFn === 'function' 
    ? outputOrFn(context)
    : outputOrFn;
  if (resolved) {
    if (Array.isArray(resolved)) {
      resolvedOutputs.push(...resolved);
    } else {
      resolvedOutputs.push(resolved);
    }
  }
}

// After:
const resolvedOutputs = resolveSpecs(definition.outputs, context);
```

### Phase 3: Dispatcher (`machinery/shuttle/hookups/index.ts`)

The dispatcher stays in **shuttle** — treadle-kit just imports and calls it:

```typescript
// machinery/shuttle/hookups/index.ts
import { detectHookupType } from './types.js';
import { applyAndroidManifestHookup } from './android-manifest.js';
import { applyCargoTomlHookup } from './cargo-toml.js';
// ... etc

export interface HookupResult {
  path: string;
  type: HookupType;
  status: 'applied' | 'skipped' | 'error';
  message?: string;
}

/**
 * Run all hookup specs.
 * Called by treadle-kit Phase 3.
 */
export async function runHookups(
  hookups: HookupSpec[],
  context: GeneratorContext
): Promise<HookupResult[]> {
  const results: HookupResult[] = [];
  
  for (const hookup of hookups) {
    // Detect type from path
    const hookupType = detectHookupType(hookup.path);
    
    // Resolve full path
    const fullPath = path.isAbsolute(hookup.path)
      ? hookup.path
      : path.join(context.packageDir, hookup.path);
    
    // Route to appropriate handler
    const result = await routeHookup(hookupType, fullPath, hookup, context);
    results.push(result);
  }
  
  return results;
}

function routeHookup(
  type: HookupType,
  filePath: string,
  spec: HookupSpec,
  context: GeneratorContext
): Promise<HookupResult> {
  switch (type) {
    case 'android-manifest':
      return applyAndroidManifestHookup(filePath, spec as AndroidManifestHookup, context);
    case 'cargo-toml':
      return applyCargoTomlHookup(filePath, spec as CargoTomlHookup, context);
    case 'rust-module':
      return applyRustModuleHookup(filePath, spec as RustModuleHookup, context);
    case 'gradle':
      return applyGradleHookup(filePath, spec as GradleHookup, context);
    case 'npm-package':
      return applyNpmPackageHookup(filePath, spec as NpmPackageHookup, context);
    case 'file-block':
      return applyFileBlockHookup(filePath, spec as FileBlockHookup, context);
    default:
      throw new Error(`Unknown hookup type: ${type}`);
  }
}

// Re-export types
export * from './types.js';
```

| Function | Used By | Purpose | New Home |
|----------|---------|---------|----------|

**Key principle**: The shuttle carries the hookups. Treadle-kit just resolves specs and calls the shuttle.

## Benefits

1. **Zero Boilerplate**: No custom functions for standard hookups
2. **Type-Safe**: Full TypeScript intellisense based on path
3. **Self-Documenting**: The path tells you what it does
4. **Discoverable**: IDEs suggest available fields per file type
5. **Idempotent**: All underlying handlers use marker-based blocks
6. **Testable**: Each handler can be unit tested independently
7. **Extensible**: New file types = new handler, no API changes
8. **DRY**: `spec-resolver.ts` abstracts the common func/array pattern

## Open Questions

1. **AIDL Generation**: Should AIDL be a separate hookup type or part of android-manifest?
   - Proposal: `AndroidManifestHookup.aidlInterfaces: AidlInterface[]`

2. **Conditional Hookups**: Should we support `if: (ctx) => boolean` in addition to `condition`?
   - Already supported via `condition` property

3. **Template Strings**: Should hookup content support EJS templates like outputs?
   - Proposal: Yes, with same `data` and `methods` context

4. **Multiple Files**: Should we support glob patterns in paths?
   - `path: '**/AndroidManifest.xml'` — apply to all manifests
   - Could be useful for monorepos
